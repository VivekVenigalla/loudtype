# Loudtype

**Live captions that sound like you.** A live caption overlay for streamers: loud words are big and heavy, whispers small and light, held words stretch wide, and each line is tinted with its emotion. Words never move off one shared baseline.

Built for **Hacklanta '26, Creative track (Adobe)**, also entered for MLH Best Use of ElevenLabs and the Zero Data Challenge. The original product spec was pasted in chat (not in the repo); its essentials are summarized below. `DEMO.md` holds the judging-table script and Q&A; `RUN.md` the quick-start.

## Run

```bash
npm install
npm run setup                    # one-time: GoEmotions + voiceprint (WeSpeaker) models + Roboto Flex into models/ and fonts/
cp config.example.js config.js   # add ELEVENLABS_API_KEY (config.js is gitignored and already exists locally)
npm run emotion2vec:setup        # one-time: Python venv (torch + funasr) for the voice-emotion service
npm run emotion2vec              # optional, separate terminal: emotion2vec_plus_large on 127.0.0.1:7790 (~1.2 GB model, downloaded once)
npm start                        # http://localhost:7777/control/ and /overlay/
npm test                         # node:test, no network; starts its own server on a free port
npm run typecheck                # tsc over the DOM-free modules (JSDoc types, nothing compiled)
```

- If `npm start` says port 7777 is in use, a server is already running: `lsof -ti tcp:7777 | xargs kill`.
- The user usually runs the server in the Terminal panel (tab 0). Don't start a second one; reload the pages instead. Server code changes need a restart; `control/`, `overlay/` changes only need a page reload.
- **The folder name `HacklantaFinal?` contains a `?`.** It breaks shell globs and `import()` of plain paths in Node. Always quote paths and use `pathToFileURL` in scripts. Recommend renaming to `Loudtype` (outside a Claude session running in it).
- Git repo since the codebase audit (`main` = baseline, audit work on branch `audit`). `models/` and `config.js` are gitignored.

## Architecture

```
Control panel (Chrome, /control/)            Overlay (/overlay/, OBS Browser Source)
  mic → AudioWorklet (pcm-worklet.js)          renders words on one baseline,
    ├─ 33 ms frames: dB + voicing ─┐           chunks, fades, colors, prompt card
    └─ 100 ms 16 kHz PCM → Scribe  │                    ▲
  ElevenLabs Scribe realtime (stt.js)          ws://localhost:7777/relay (server.js)
    partial / committed+timestamps ─┤                    │
  prosody.js: level per word ◄──────┘          caption events (JSON) ─┘
  emotion.js + emotion-core.js: line emotion
```

- **server.js** (Node, only runtime dep `ws`): serves `control/ overlay/ fonts/ models/ replay/` (whitelisted top-level dirs only, checked in `server-paths.js` *after* resolving `..`, so `config.js` and `server.js` are never served), streamed, maps `/vendor/transformers/` → `@huggingface/transformers/dist` and `/vendor/ort/` → `onnxruntime-web/dist`. `GET /token` mints a single-use Scribe token (API key never reaches the browser). `GET /config` returns config minus the key. `/relay` rebroadcasts control → overlay; stores nothing.
  - Security rules (each has a test in `test/server.test.js`): only loopback `Host` headers are answered (DNS rebinding); the relay only accepts an `Origin` from this server; a malformed request gets 400/404, never a crash. Every response carries COOP/COEP (cross-origin isolation → the emotion model runs on 4 threads, ~2× faster per line); so pages must not load anything from another origin.
  - `LOUDTYPE_PORT=7791 node server.js` runs a second copy for testing next to the user's server on 7777.
- **control/**
  - `app.js`: UI wiring: session start/stop, Scribe reconnect (up to 3 tries, calibration kept; auth/quota errors stop), replay, export, Director's View, mood hotkeys, judge prompt cards. `latest` = the newest session (running or stopped); only it may send, log or export. Director's View shows the mic and whether Chrome honored auto gain/noise suppression off, the room noise floor, and **Copy mic report** (JSON of the last 40 words' dB, vs-normal, voicing, level, plus `heardVsShown`: each line as Scribe committed it vs. what was captioned, to tell lost-by-Scribe from lost-by-Loudtype; also `window.loudtype.micReport()`): ask the user for it when tuning a real mic. `window.loudtype.session()` exposes the live session for debugging.
  - `transcript.js`: the partial → commit → timestamped-commit state machine (no DOM; dependencies injected). Waits 600 ms for the timestamped commit; a late one upgrades the line in place. Keeps the session's exportable `lines`; word times stay on the session clock across reconnects (`origin`).
  - `caption.js`: the shared grammar (levels, level order, icons, emotion colors, model id) and the JSDoc types of the caption event. `overlay/style.css` repeats the colors; `test/caption.test.js` keeps them in sync.
  - `audio.js` + `pcm-worklet.js`: mic with AGC/noise suppression **off** (they'd flatten loudness). **Source** select: Microphone, or **Tab audio** (`getDisplayMedia` with tab audio; the video track is dropped; for testing on real Twitch/YouTube streams; Chrome's Stop sharing ends the session). The worklet input is mixed down to mono (`channelCount: 1`, explicit). All measurement happens **in the worklet** with exact `currentTime` stamps; main-thread timing was ~0.5 s off while the model loaded.
  - `features.js`: per-frame `{db, voicing}`; voicing = normalized autocorrelation peak at 70–400 Hz (whispers ≈ unvoiced). Shared by worklet and eval scripts.
  - `prosody.js`: learns the speaker's normal level (median of the first 6 *voiced* words), then levels by fixed dB offsets: whisper ≤ −10 or (voiced share < 0.3 and < +4 dB), soft ≤ −6, loud ≥ +6 (were ±5: normal speech wobbles to +5.1 and jumped size), shout ≥ +8; all divided by `sensitivity` (control-panel slider 0.5–1.5, `Prosody.thresholds()`) (was +10: on AirPods real shouts measured +8.2…+9.7 because the earbuds compress loud input; the laptop mic gave +14…+15; normal speech peaked at +5.1). "Normal" slowly tracks the speaker (only from normal words). Noise floor = 10th percentile of the last 15 s (5 s of nonstop talking pulled it up into the voice), clamped ≥ −72 dB. A committed word whose timing lands on a pause (no speech frames, within 3 dB of the floor) stays normal and teaches nothing. Width (`wdth` 100–151) from ms-per-letter vs. the speaker's median. `styleLive()` styles partial words instantly; committed timestamps then correct them.
  - `stt.js`: Scribe realtime (`commit_strategy=vad`, `include_timestamps=true`, `vad_silence_threshold_secs` from config). Warnings surface in the status line.
  - `emotion.js` / `emotion-core.js`: GoEmotions (`SamLowe/roberta-base-go_emotions-onnx`, q8, local only) → pos/neg/neutral, a stream-slang regex layer, and energy = mostly voice levels + some text arousal. Quadrant: pos+high → happy ★ yellow, pos+low → calm ● green, neg+high → angry ▲ red, neg+low → sad ▼ blue; neutral/low confidence → white.
  - Creator hype (`emotion-core.js`): GoEmotions reads "oh my gosh look at this" as *surprise*, neither positive nor negative, so it stayed white. surprise + ½·(excitement + amusement) ≥ 0.3 with energy ≥ 0.55 and negatives < 0.3 → happy. Tested on a MrBeast video (tab audio): almost every line was white because the words are neutral ("this is the one dollar room") and energy is measured against a speaker whose normal is already hype (and the audio is compressed). Only the hype rule is in so far; the voice side waits for real audio (Director's View **Save last 60 s audio** → WAV on click; mic report `heardVsShown[].emotion` has each line's result, energy, text scores, tone features).
  - `tone.js`: **voice tone per committed line** vs. that speaker's normal (their profile): loudness (dB), pitch (semitones vs. their normal pitch), pitch range (p10–p90 st), voiced share, pace. `toneEnergy()` = 0.5 + 0.05·pitch + 0.03·loud + 0.015·(range − 9) → the energy that splits happy/calm and angry/sad (before: only the word sizes, which are mostly "normal" now, so excited lines read calm). Valence still comes from the words: neutral words spoken with feeling stay white (the voice alone couldn't tell happy from angry; white beats a wrong color). Falls back to word sizes before a speaker is calibrated. **Teach your tones** (`ToneBook`, judge prompt cards 2–4): the judge says "The next round starts in two minutes" happy, angry, sad; card 1 teaches their neutral voice. A later line whose loud/pitch/range/rate (scaled 4 dB, 3 st, 4 st, 1.2 w/s) is ≤ 0.6× as far from a taught mood as from neutral and ≤ 0.8× the next mood takes that mood, even over neutral words (the voice wins: sarcasm too). A mood only counts if it sounded ≥ 1.5 units from their neutral voice; otherwise the status asks them to exaggerate and redo the card. Per speaker (profile), memory only; New judge forgets. While a teach card is up the line shows the mood being taught. Generic voice-emotion models tried and dropped (both heard nothing on neutral words): `wav2vec2-base-superb-er` (9/36) and audEERING `wav2vec2-large-robust-12-ft-emotion-msp-dim` (660 MB; arousal/valence ~0.5 on every neutral-words line). On the ElevenLabs set the taught moods are < 1.5 apart (subtle acting), so it falls back and matches the tone system (held out 12/18); unit tests cover acted delivery; not yet tried with a real person.
  - `relay.js` (ws client + in-memory `Recording` for replay, last 10 minutes only), `export.js` (`.srt` + ExtendScript `.jsx`; **ES3 only** and **pure ASCII** in generated code).
- **overlay/** `render.js`: **roll-up captions in one lane**. Words append to the bottom row; when it's full that row moves up and the oldest row drops (no clearing between sentences, so earlier words stay for context). At most 2 rows on screen; the captions fade after 6 s of silence. Rows are left-aligned and break only at positions that depend on earlier words, so nothing reflows as words arrive (row jumps are instant, no animation; this deliberately relaxes the spec's "no vertical movement" for readability, by request). Per-word emotion color + an icon token opening each tinted line. Staggered 90 ms fade-in per word (classes removed on `animationend` so moving rows never replays it). `style.css`: Studio pack, per-level outlines (thin for whispers, heavy for shouts), word spacing in `em` of each word, colorblind palette via the `.colorblind` class.

**Caption event** sent to the overlay (typed as `CaptionEvent` in `caption.js`): `{type:'line', line, final, provisional, emotion, confidence, words:[{word, level, size, wght, wdth, start?, end?, event?}]}`. Other types: `calib {progress}`, `pack {pack}`, `font {font}`, `motion {reduce}`, `prompt {text, step, of}`, `clear`; overlays send `hello` on (re)load.

**Main speaker only** (`IGNORE_BACKGROUND`, checkbox "Main speaker only", off by default): calibration also learns the main speaker's pitch (`features.js` now returns `pitch`). Two layers: `gate.js` in the worklet silences audio under max(normal − 18 dB, noise + 6) before Scribe (150 ms lookahead, 350 ms hangover; chunk times shifted by the delay), and `prosody.background()` drops clearly voiced (≥ 50%) words that are > 12 dB under normal, or 3–12 dB under at a pitch outside −5…+7 semitones; whispers (unvoiced) are always kept; a line mostly someone else's is dropped whole. Loud unvoiced bursts (claps, bumps) never read loud. Tests: `test/ballroom*.test.js` (synthetic + real `say` voices via `scripts/scenes.mjs`), `node scripts/eval-ballroom.mjs` (Scribe, ~1 min quota): main speaker 35/35 kept, nearby talker 1/14 captioned (was 14/14). Known limits: in loud chatter the gate stays open (word filter does the work); a same-pitch person leaning in (within 3–12 dB) is captioned; chatter words timed onto a pause (silent path) are kept.

**Voiceprints: only calibrated voices are captioned** (`voiceprint-core.js` logic, `voiceprint.js` model loader, `ml.js` shared transformers.js setup). On a MacBook mic, someone 2–3 m away is only ~2–9 dB quieter than the speaker, so level and pitch alone can't separate them. Model: `onnx-community/wespeaker-voxceleb-resnet34-LM` (CC-BY-4.0, fp32 26 MB, on-device, ~20–30 ms per line). Enrollment = the calibration words (loudest-voice cluster) plus up to 3 s more of the speaker's words until the voiceprint exists (`Prosody.enrollSpans`; 6 words alone, ~1 s, enrolled too weakly and dropped the speaker's next line in the browser test). The worklet sends pre-gate 16 kHz audio with each chunk into an `AudioRing` (last 60 s, memory only). Each committed line is embedded before styling (`transcript.identify` → `prosody.voice`): "Voice filter" select: **relaxed** (default) cosine ≥ 0.5 match, < 0.25 other (lines < 1 s: 0.45 / 0.15); **strict** 0.6 / 0.45 (0.55 / 0.3); else unsure → level/pitch rules. Strict rejected the user's own lines on the MacBook mic, hence relaxed. Lines judged 'match' (≥ 1 s) refine the voiceprint (centroid of enrollment + last 8). Margin note: eval strangers scored ≤ 0.20, under relaxed's 0.25. 'other' drops the whole line incl. whispered words; whispered lines (< 35% voiced) are never judged. Partials: shown at once (waiting for the first check made the speaker's words late) and hidden while a check says 'other'; partial words that level/pitch call background wait for the commit. Multi-speaker: one voiceprint per profile; a sure match (best beats next by 0.08) assigns the line to that profile, else per-word pitch/level matching. Director's View shows "Voiceprint: n/n enrolled · last line: you ✓ (0.68)". Gate: never above normal − 8 dB (the speaker's own words always pass); before calibration/while enrolling noise + 5 (was + 10: on a laptop mic the voice is only ~12 dB over the room, so calibration speech was cut). Unvoiced frames (whispers) open it from max(noise + 3, normal − 22) for 150 ms (on the Mac mic whispers sit ~8 dB under normal, only ~6 dB over the room, and were cut before). Scribe's `filter_background_audio` can't be combined with `include_timestamps` (Scribe rejects it), and `vad_threshold` 0.6 didn't help (eval-ballroom --mac), so neither is used. Results: `node scripts/eval-voiceprint.mjs [--mac]` (offline, real model): 8/8 lines right on both mics; browser fake-mic test with the Mac scene via Scribe: all 6 main-speaker lines kept (whisper and shout styled), all 3 stranger lines dropped, no stranger partial ever shown. Limits: lines under ~1 s are often 'unsure'; a stranger whispering into the mic is kept; a voice similar to the speaker's (same-engine TTS scored up to 0.59) can pass; real humans and real rooms not yet measured, so the thresholds may need tuning from Director's View readings.

**One speaker, no labels (2026-10-11).** The label-everyone mode (S1/S2 chips by voiceprint diarization, per-speaker loudness profiles, lanes per speaker, `splitTurns`, `speakers.js`) was removed by request: it didn't work reliably on real mics (a MacBook mic split one person into several speakers whose lanes pushed words off screen; similar voices merged). Default now: everyone is captioned as one stream against one calibrated loudness profile (`Prosody`, `focus = false`, no gate, no voiceprint). "Main speaker only" (`IGNORE_BACKGROUND`) is unchanged. Caption events and exports carry no `speaker`. The old code is in git history (commit 66ed718 and earlier) if multi-speaker comes back.

**Second-pass transcript + voice emotion (2026-10-10).** Latency matters less than quality (streams are delayed 5–10 s).
- `STT_REFINE` (default on): each committed line's audio (from the `AudioRing`) goes to `POST /transcribe` → server → ElevenLabs batch `scribe_v2` (`STT_BATCH_MODEL_ID`), word timestamps; `transcript.refine` replaces the realtime words before styling (punctuation, casing, better words; ~0.4–1 s). Fails → realtime words kept. The plan rejects ZRM (`enable_logging=false`) with 403; the server retries once with logging and remembers. Costs batch quota on top of realtime.
- `EMOTION2VEC` (default on, inert when the service is off): `emotion2vec/service.py` (Python, funasr, `emotion2vec/emotion2vec_plus_large`, 127.0.0.1 only, memory only) proxied at `POST /emotion2vec` (same origin, COEP-safe). Both endpoints: POST + own Origin only (403 otherwise). `fromVoice()` maps its 9 labels to quadrants (no calm label: happy at low tone energy → calm); `fuse()` lets it color a line **only when the words are neutral and it is ≥ 0.9 sure** (`VOICE_FUSION`). Measured on the acted set (`node scripts/eval-emotion2vec.mjs`, `eval-emotion-voice.mjs`): alone 15/36 (very bimodal; read calm lines as happy, "unfair!" as sad); fused 24/36 = same as text+tone, no regression, no gain on TTS acting. Real voices still untested.

**Sync mode, sound tags, After Effects animations (2026-10-11).**
- **Sync mode** (`control/sync.js` `CaptionSync`, control "Stream delay" field, `STREAM_DELAY_SECS`, remembered per browser): with a delay > 0 each finished line is held and its words go to the overlay one by one at spoken time + delay (AudioContext clock: `transcript.origin + word.start`), so captions land when viewers of the delayed stream hear them, already final (partials never shown; a late line catches up at once). The panel shows how long after a line STARTS it is finished (median / 90th percentile) and the delay to set. Measured with real Scribe (fake mic, 4 lines): word spacing on the overlay matched the speech exactly; finished ~3.5 s after a line starts without the second pass, ~4.3 s (slow 5.4 s) with it → 6 s suggested. Browser gotcha (fixed, tested): `setTimeout` must not be stored and called as a method (`this.setTimer = setTimeout` → "Illegal invocation" in Chrome, fine in Node).
- **Sound tags**: the second pass asks Scribe v2 for `tag_audio_events`; `[laughs]`, `[sighs]`, `[applause]`… become caption tokens (`word: '[laughs]'`, `event: 'laughs'`): never styled by loudness, smaller + italic (`.w.event`), laughter hops (`SOUND_FX` in fx.js), kept in `.srt`/AE text (subtitles for deaf viewers mark sounds this way). The emotion model reads only the spoken words; `withSounds()` (emotion-core.js) colors a line the words left neutral: laughter → happy, gasps → surprised, crying → sad, screams → scared (sighs/applause/music: no change). The second pass hears up to 1.5 s around the line (laughs often come just before/after the words) but never audio a previous line already sent; `transcript.refine` keeps only this line's words (±0.3 s) and sound tags not yet captioned (`soundsUntil`). Scribe tagged ElevenLabs-acted laughs and sighs; it did not tag an acted gasp.
- **After Effects export animations**: `aeFx()` in export.js turns each emotion's overlay animation into text animators (Position/Scale/Skew/Opacity) driven by an Expression Selector (based on words) whose amount expression has the line's word times baked in, so each word animates from when it appears. Named `Loudtype <emotion> <effect>`; each one is wrapped in try/catch (a failure only skips that animation and alerts once). Tests evaluate every expression like AE would (textIndex, time). **Never run inside After Effects** (not installed here): the matchnames (`ADBE Text Expressible Selector`, `ADBE Text Range Type2` for Based On, `ADBE Text Position 3D`…) are from memory.
- `STT_REFINE` and `EMOTION2VEC` now default to ON when absent from config.js (the user's config.js lacked both, so the second pass had silently never run).

**Look, stream-safe and exports (2026-10-14).**
- **Style packs** (`PACKS` in caption.js, control select / `DEFAULT_PACK` / `?pack=`): Studio (white, black outline), Arcade (neon, heavy outline, hard offset shadow), Ink (dark text, white outline, for bright footage). Palette, outline and shadow only (`--outline`, `--shadow`, `--shadow-quiet`, `--shadow-loud`, `--c-*` on `.pack-<id>`); the type grammar is the same in every pack. Provisional tints mix with the pack's `--c-neutral`. The colorblind palette comes after the packs in style.css, so it wins (tested).
- **Caption size and position** (`SIZES`, `POSITIONS`; control selects, `CAPTION_SIZE` / `CAPTION_POSITION`, `?size=s|m|l|xl`, `?position=top`): sets `--base` (44/56/72/90 px) and moves the stage to the top (the prompt card then moves to the bottom). Overlay event `{type:'layout', size, position}`. Pack, font, size, position and motion are remembered per browser and re-sent when an overlay says `hello` (a reload of the OBS source used to lose the pack). URL parameters win over the panel.
- **Stream-safe** (`control/safe.js`, checkbox, `STREAM_SAFE`, remembered per browser): swear words and slurs → `#@%!` keeping punctuation, size, weight, color and timing; applied where captions leave for the overlay (`CaptionSync.out`) and to exports; the emotion model and the control-panel log still see the real words. Whole-word patterns (tested against ~30 look-alikes: class, assist, Dickens, cocktail, Scunthorpe...). Also masks words speech-to-text already starred (`f***`).
- **Exports**: `.vtt` (WebVTT: STYLE block with loudness and emotion classes, `<c.shout>`, per-word `<hh:mm:ss.mmm>` timings, emotion icon, sound tags in `<i>`, markup escaped) and a plain transcript `.txt` (`[mm:ss] (mood) text`). All exports sort lines by spoken time (lines can finish out of order when a later line's second pass returns first; `transcript.lines` is also kept in order).
- **Hotkeys**: ← → prompt cards, N New judge (plus 1–7/0 moods).

## Design rules (from the spec; don't break them)

- One baseline per row. Motion: the ~80 ms fade-in, the optional 108% shout pop, and (by request, 2026-10-10) **one animation per emotion**, played once when a line's emotion is final (`overlay/fx.js`, Web Animations so row re-layouts don't restart them; approved on `/overlay/preview.html`). Words return to the baseline at rest; angry rests at scale 1.06 and sad at 0.85 (transform, no reflow; `style.css` and the last keyframe must match, tested). Approved 2026-10-10: happy wave, angry shake, scared tremble, disgusted lean; revised then: calm breathes (word i slides i × 0.09 em right and back, twice, all words in step), sad shrinks and stays small, surprised pops every word at once (`together`: no stagger, fade-in too). **Reduce motion** (control checkbox, `REDUCE_MOTION`, `?motion=reduce`, or the OS setting) turns off emotion animations and the pop; color, icon and the angry size stay. (Also by request: roll-up rows jump up one row instantly when the bottom row fills.)
- Each visual property means one thing: size+weight = loudness, width = held length, color+icon+animation = emotion. Color is never the only signal (icons).
- Emotions (2026-10-10): happy ★, calm ●, angry ▲, sad ▼ plus **surprised !** (orange), **scared ◇** (purple), **disgusted ✕** (olive). Text: a negative line that is mostly fear/nervousness → scared, mostly disgust → disgusted; surprise with no excitement/amusement → surprised (with some → hype happy) (`SPECIFIC` in emotion-core.js). emotion2vec's surprised/fearful/disgusted map straight across. Hotkeys 5/6/7. `node scripts/probe-emotion.mjs "line" ...` shows text scores + result (offline).
- Subtitle fonts (`FONTS` in caption.js, control select / `CAPTION_FONT` / `?font=`): Roboto Flex (default), Comic Neue, Inter, Atkinson Hyperlegible Next; OFL, from pinned `@fontsource` devDependencies, copied into `fonts/` by `npm run setup`. Comic Neue has fixed weights 300/400/700 (`font-weight` follows `--wght`); only Roboto Flex has the width axis. The control panel re-sends font/motion when the relay opens and when an overlay says `hello` on (re)load.
- Only tint when confident; a white line beats a wrong color.
- Zero data: no accounts or analytics, nothing written to disk except on Export/Save click, emotion runs on-device, only outside host is ElevenLabs.
- Levels: whisper 0.75×/wght 220, soft 0.9×/350, normal 1×/450, loud 1.25×/700, shout 1.6×/1000.

Run it after every change. `npm run typecheck` too.

Last result (2026-10-10, shout threshold +8): 46/51 exact, 51/51 within one level. Misses: 4 whispers read as soft (same as before), and "so" in the +7 dB "loud" sentence now reads as shout (the clip's loud segment sits 1 dB under the new line; accepted to catch real AirPods shouts). With +10: 47/51, and 48/51 before the silent-word fix (Scribe tokenizes differently each run and the clip's noise is random, so ±1 is normal). Old z-score method: 44/51.

- `node scripts/make-emotion-set.mjs` (once, ~1.8k chars of ElevenLabs TTS quota): 36 lines acted with Eleven v3 tags (2 voices; groups: words+tone agree, neutral words with emotional tone, plain neutral) into `eval-data/emotion/` (gitignored). `node scripts/eval-emotion-voice.mjs [--dump]`: offline; tunes on voice A, holds out voice B. Delete test WAVs afterwards.
- `node scripts/make-demo.js` regenerates the scripted offline clip `replay/demo.json`.
